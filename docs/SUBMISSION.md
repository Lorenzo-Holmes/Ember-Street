# Ember Street — Submission Checklist

## 目标版本

- 产品：Ember Street / 余烬长街
- 候选版本：**v0.5.0 — Living Street**
- 定位：**文字末日生存模拟 × 跑团判定 × 避难街经营 × 七格守夜**
- 目标：小红书 Vibecoding 比赛版
- 范围：第一章 DAY 1–30 + 每日挑战 + 本地分享

## 构建前

```bash
npm install
npm run typecheck
npm test
npm run build
npm run cf:dry-run
```

全部必须成功；GitHub Actions `CI / verify` 必须为 green。

## 核心体验验收

- 首次打开无需登录。
- NIGHT 1 在约 10–15 秒内可完成第一次三合与首单。
- 首单具有约 30 秒阅读 / 操作窗口。
- 主配给台始终只有 7 格。
- 每个货架同类物资按 3 件一批补货。
- 请求之间有约 2.5–3 秒安静窗口。
- 白天拥有「街区 / 行动 / 日志」三个主要入口。
- DAY 1–30 每天至少存在一个街区状况。
- Story Pool 不一次性把所有内容塞给玩家。
- 不确定行动使用 2D6 / 优势劣势判定。
- 投骰结果立即保存，刷新不能刷骰。
- 事件结果写入日志并实际改变资源 / 人物 / Story Flags / 防线 / 电力。
- DAY 10、DAY 20 为阶段尸潮。
- DAY 30 为最终尸潮，约 120 秒。
- DAY 7 不触发章节完成。
- DAY 30 失败后可重整再战，不进入 DAY 31。
- DAY 30 成功后第一街段进入章节完成状态。

## 生存与跑团验收

- 口粮按居民规模真实消耗，并以语义状态呈现。
- 药品用于白天治疗，并可在夜间提供一次医疗请求容错。
- 防线越好，尸潮压力增长越慢。
- 电力过低会明显增加夜间尸潮压力。
- 轻伤会影响工作效率，休息可以恢复。
- 幸存者岗位能改变下一夜资源 / 压力 / 请求容错。
- 专长、信任、伤病、建筑和 Story Flags 能进入骰子修正。
- 双六 / 双一产生不同叙事后果，但第一章不永久死亡。
- 信任 3 的适用人物可获得一次最低骰重投。

## 事件内容验收

- Living Street 系统内容节点总量 >= 90。
- 地点链至少覆盖药店、居民楼、超市、修车铺、地下车库等。
- 6 名主要幸存者均存在人物事件或判定关联。
- 无选择环境日志能持续提供世界变化感。
- DAY 5 / 10 / 15 / 20 / 25 有阶段夜间突发。
- DAY 30 有两个关键夜间判定。
- 前 29 天获得的关键 Story Flags 能影响 DAY 30。

## 留存与分享验收

- 主线存档刷新后可恢复。
- 切后台 / pagehide 强制保存关键状态。
- 已投骰结果恢复后不变化。
- 每日挑战不修改主线存档。
- 同日期挑战使用固定 Seed。
- `ES1-...` 挑战码带校验。
- 分享卡完全在本地 Canvas 生成 PNG。
- 离线备货最多 6 小时，不自动推进 DAY / 事件 / 尸潮。

## 自动化验收

必须覆盖并通过：

- 七格 / 三合 / 批次货架
- 首单节奏 / 请求降频
- 建筑与岗位
- 固定章节事件 / 日志 / 黄昏门槛
- DAY 1–30 每日街区状况
- Living Street 内容节点下限
- 2D6 确定性、优势 / 劣势
- 已落地骰子刷新不可重投
- 生存状态、低电力、药品夜间容错
- 伤病与休息恢复
- Combo / 紧急清台
- 离线 / 小灰 / 自动排班
- 每日挑战 / 挑战码
- **NIGHT 1 → DAY 30 第一章完整贯通**

## 移动端人工验收

重点 viewport：360×800、375×812、390×844、393×873、412×915、430×932。

检查：

- 无意外横向滚动。
- 七格与四货架在竖屏内可稳定操作。
- 重要触控区域约 44px 或以上。
- 事件、骰子和结果按钮不被底栏遮住。
- 日志长内容可自然滚动。
- iOS / Android safe area 不遮挡核心按钮。
- 切后台 / 锁屏后返回没有重复计时器。
- 音频、震动、Clipboard 等 API 不可用时自然降级。
- `prefers-reduced-motion` 下骰子与规则仍可理解。

## 性能验收

- 不创建大规模僵尸寻路。
- 夜间逻辑按真实 elapsed time 运行，不依赖固定 FPS。
- React 不承担每帧粒子 / 僵尸状态。
- 夜间 localStorage 普通写盘节流；关键骰子立即保存。
- 白天主要使用 DOM / CSS 静态表现。
- 骰子使用 CSS / DOM，不引入 3D 运行时。
- Canvas 分享卡只在用户主动生成时创建。
- 不加载在线字体、大视频、Three.js / Unity WebGL 等大型运行时。

## 提交笔记传播重点

第一句优先表达体验，而不是技术栈：

> 我用七个格子守了 30 个夜晚，每一次骰子都可能把这条街改写。

建议素材顺序：

1. NIGHT 七格配给 + 夜间动态日志
2. 2D6 跑团判定动画
3. 白天地点 / 人物事件选择
4. DAY 1 → DAY 30 街区与人物成长
5. DAY 10 / 20 / 30 尸潮升级
6. DAY 30 最终两次关键判定
7. 小灰 / 每日挑战 / 分享卡

技术说明放后半部分：纯前端、无服务器、Seed 可复现、AI 辅助 Vibecoding。

## v0.5.0 冻结原则

进入投稿与人工 QA 阶段后，不再增加：第二章、第四物资链、武器战力、抽卡、联盟、PVP、复杂技能树或大型 SLG 系统。

只允许：

- 阻断 Bug
- 30 天平衡调整
- 移动端布局与可读性
- 性能问题
- 音效 / 动画 / 美术微调
- 分享与投稿包装
- 平台审核所需改动
