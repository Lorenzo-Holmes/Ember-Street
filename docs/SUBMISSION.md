# Ember Street — Submission Checklist

## 目标版本

- 产品：Ember Street / 余烬长街
- 候选版本：v0.3.0
- 目标：小红书 Vibecoding 比赛版
- 范围：第一章 DAY 1–7 + 每日挑战 + 本地分享

## 构建前

```bash
npm install
npm run typecheck
npm test
npm run build
```

四项必须全部成功；GitHub Actions `CI / verify` 必须为 green。

## 功能验收

- 首次打开无需登录。
- 10–15 秒内可以完成首个三合与第一份请求。
- 主配给台始终 7 格。
- 满格后出现主动紧急清台，不产生软死局。
- NIGHT 1 结束后可进入街区并修复搜索站。
- DAY 1–7 能连续推进。
- DAY 7 尸潮失败后重试 DAY 7，不进入 NIGHT 8。
- DAY 7 成功后显示第一章完成。
- 幸存者岗位影响下一夜资源 / 尸潮压力 / 请求耐心。
- 主线存档刷新后可恢复。
- 每日挑战不会修改主线存档。
- 挑战码同 Seed 可复现并有校验。
- 分享卡完全在本地生成 PNG。

## 移动端验收

重点 viewport：

- 360×800
- 375×812
- 390×844
- 393×873
- 412×915
- 430×932

检查：

- 无横向滚动。
- 七格与四个货架在竖屏可操作区域内。
- 重要触控区域约 44px 或以上。
- iOS / Android safe area 不遮挡核心按钮。
- 切后台 / 锁屏后返回，关键状态不丢失。
- 音频或震动 API 不可用时游戏仍可玩。
- `prefers-reduced-motion` 下不影响规则。

## 性能验收

- 不存在独立大规模僵尸寻路。
- 夜间逻辑使用 elapsed time，不依赖固定 FPS。
- 夜间 localStorage 写盘已节流。
- Canvas 分享卡只在用户主动生成时创建。
- 不加载在线字体、大视频、Three.js / Unity WebGL 等大型运行时。

## 生产包原则

生产包只包含运行必需的静态构建产物，不包含：

- `node_modules/`
- `.git/`
- 测试源码（除非平台直接从源码构建）
- 开发截图
- QA 临时文件
- 无关文档

若小红书平台要求上传源码 ZIP，则以平台当日文档要求为准；若支持静态成品，则优先使用 `dist/` 内容。

## 提交笔记传播重点

第一句不要讲技术栈。优先表达：

> 只有七格，我在尸潮夜里把最后一盏灯守到了天亮。

建议展示：

1. NIGHT 七格玩法
2. DAY 1 与 DAY 7 街区变化
3. 尸潮之夜
4. 镇街猫 / 幸存者
5. 每日挑战与挑战码

技术说明放到后半部分：纯前端、无服务器、Seed 可复现、AI 辅助 Vibecoding。

## 冻结原则

候选版本进入投稿阶段后，不再增加大系统。只允许：

- 阻断 Bug
- 移动端布局问题
- 性能问题
- 文案 / 美术微调
- 平台审核所需改动
