# Ember Street — Submission Checklist

## 目标版本

- 产品：Ember Street / 余烬长街
- 候选版本：**v0.4.0 — Survival Narrative**
- 定位：**文字末日生存模拟 × 避难街经营 × 七格守夜**
- 目标：小红书 Vibecoding 比赛版
- 范围：第一章 DAY 1–7 + 每日挑战 + 本地分享

## 构建前

```bash
npm install
npm run typecheck
npm test
npm run build
npm run cf:dry-run
```

全部必须成功；GitHub Actions `CI / verify` 必须为 green。

## 核心体验验收

- 首次打开无需登录。
- NIGHT 1 在约 10–15 秒内可完成第一次三合与首单。
- 首单具有约 30 秒阅读 / 操作窗口。
- 主配给台始终只有 7 格。
- 每个货架同类物资按 3 件一批补货，不会每点一次就换品。
- 请求之间有约 2.5–3 秒安静窗口。
- DAY 1 天亮后进入余烬日志与白天街区。
- 白天拥有「街区 / 行动 / 日志」三个主要信息入口。
- 当天文字事件未解决前不能直接进入黄昏。
- 事件选择显示成本 / 风险，不可承担的选择会被禁用。
- 事件结果写入余烬日志并实际改变资源 / 人物 / 防线 / 电力。
- 黄昏页面能明确看到今晚的口粮、防线、电力和人员准备。
- DAY 1–7 可连续推进。
- DAY 7 为 90 秒尸潮之夜。
- DAY 7 失败后重整再战，不进入 NIGHT 8。
- DAY 7 成功后第一街段进入章节完成状态。

## 生存系统验收

- 口粮按居民规模真实消耗，并以“短缺 / 还能撑几天”等语义呈现。
- 药品用于白天治疗，并可在夜间提供一次医疗请求容错。
- 防线越好，尸潮压力增长越慢。
- 电力过低会明显增加夜间尸潮压力。
- 轻伤会影响人物工作效率，安排休息可以恢复。
- 幸存者岗位能改变下一夜资源 / 压力 / 请求容错。
- 第一章不发生永久角色死亡或长期死档。

## 留存与分享验收

- 主线存档刷新后可恢复。
- 切后台 / pagehide 会强制保存关键状态。
- 每日挑战不修改主线存档。
- 同日期挑战使用固定 Seed。
- `ES1-...` 挑战码带校验。
- 分享卡完全在本地 Canvas 生成 PNG。
- 离线备货最多 6 小时，不自动推进 DAY / 事件 / 尸潮。

## 自动化验收

必须覆盖并通过：

- 七格 / 三合 / 批次货架
- 首单节奏 / 请求降频
- 建筑与岗位
- 文字事件 / 选择成本 / 日志 / 黄昏门槛
- 生存状态语义
- 低电力尸潮惩罚
- 药品夜间医疗容错
- 伤病与休息恢复
- Combo / 紧急清台
- 离线 / 小灰 / 自动排班
- 每日挑战 / 挑战码
- **NIGHT 1 → DAY 7 第一章完整贯通**

## 移动端人工验收

重点 viewport：

- 360×800
- 375×812
- 390×844
- 393×873
- 412×915
- 430×932

检查：

- 无意外横向滚动。
- 七格与四货架在竖屏内可稳定操作。
- 重要触控区域约 44px 或以上。
- 事件正文与选择按钮不被底栏遮住。
- 日志长内容可自然滚动。
- iOS / Android safe area 不遮挡核心按钮。
- 切后台 / 锁屏后返回没有重复计时器。
- 音频、震动、Clipboard 等 API 不可用时自然降级。
- `prefers-reduced-motion` 下规则不受影响。

## 性能验收

- 不创建独立大规模僵尸寻路。
- 夜间逻辑按真实 elapsed time 运行，不依赖固定 FPS。
- React 不承担每帧粒子 / 僵尸状态。
- 夜间 localStorage 写盘已节流。
- 白天主要使用 DOM / CSS 静态表现。
- Canvas 分享卡只在用户主动生成时创建。
- 不加载在线字体、大视频、Three.js / Unity WebGL 等大型运行时。

## Cloudflare

生产从 `main` 自动部署。仓库已提供 Workers Static Assets 配置：

```bash
npm run cf:dry-run
npm run deploy:cf
```

正式发布前先保证 `main` 自己的 CI 重新全绿，不能只依赖功能分支结果。

## 生产包原则

生产包只包含运行必需的静态构建产物，不包含：

- `node_modules/`
- `.git/`
- 测试源码（若平台直接接收静态成品）
- 开发截图
- QA 临时文件
- 无关文档

若平台要求源码 ZIP，则以平台当日上传规范为准；若支持静态成品，则优先使用 `dist/`。

## 提交笔记传播重点

第一句优先表达体验，而不是技术栈：

> 只有七格，我在尸潮夜里把最后一盏灯守到了天亮。

建议素材顺序：

1. NIGHT 七格配给与尸潮压力
2. DAY 白天文字事件 / 艰难选择
3. DAY 1 → DAY 7 街区灯火变化
4. 余烬日志与幸存者状态
5. DAY 7 尸潮之夜
6. 小灰 / 每日挑战 / 分享卡

技术说明放后半部分：纯前端、无服务器、Seed 可复现、AI 辅助 Vibecoding。

## v0.4.0 冻结原则

进入投稿与人工 QA 阶段后，不再增加：第二章、第四物资链、武器战力、抽卡、联盟、PVP、复杂技能树或大型 SLG 系统。

只允许：

- 阻断 Bug
- 移动端布局与可读性
- 性能问题
- 音效 / 动画 / 美术微调
- 分享与投稿包装
- 平台审核所需改动
