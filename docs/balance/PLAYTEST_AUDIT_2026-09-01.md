# Ember Street v0.6 · DAY1→30 自动游玩审计（2026-09-01）

> 状态：第一轮机制审计完成。**本报告暂不据此改数值。** 自动策略模型用于找异常、收敛和覆盖缺口，不等同于真人胜率。

## 1. 本轮做了什么

审计分成三组并行实验：

1. 三种基线策略：谨慎 / 均衡 / 激进，各 200 局，共 600 局。
2. 九条街区原则逐条隔离，每条 80 局，共 720 局。
3. 资源压力曲线与 DAY29 六阶段选择收敛：三种策略各 120 局，共 360 局。

主报告的总样本为 **1320 局完整 DAY1→30**。所有策略批次完成率为 100%。

自动化同时输出：

- `playtest-audit.json` / `playtest-audit.md`
- `pressure-curves.csv`
- `day29-choice-convergence.json`

GitHub Actions 会把它们保存为 `ember-street-playtest-audit` artifact。

## 2. 可以直接相信的发现：夜间事件重复严重

这是本轮最稳健的结果，因为它不仅出现在模拟结果里，也能由当前调度器结构直接解释：同一夜内部是不放回抽取，但跨夜没有“最近出现过”惩罚或冷却。

600 局基线中，平均每局出现次数最高的事件：

| 事件 | 平均每局 |
| --- | ---: |
| 发电机频率突然掉了 | 19.46 |
| 围栏外有人敲门 | 15.67 |
| 东街连续脚步声 | 14.53 |
| 配给争吵 | 11.89 |
| 野狗 | 11.11 |
| 孩子噩梦 | 10.51 |
| 北侧围栏松动 | 9.37 |
| 居民高烧 | 9.22 |
| 问起失踪者 | 9.06 |

共有 **24 个夜间事件平均超过 1.25 次/局**。

### 结论

下一轮内容修复的最高优先级应该是 **跨夜反重复机制**，而不是继续加事件数量掩盖问题。

建议目标：

- 普通事件出现后至少 2–4 天明显降权；
- 同类别连续出现也应轻度降权；
- 紧急事件和尸潮阶段可以豁免或采用更短冷却；
- 30 天单局内，普通事件的 P90 重复次数尽量压到 3 次以内；
- 保留因果加权：如果玩家长期不守夜，威胁事件仍应更常见，但不应每天都是同一张卡。

## 3. DAY29：六个阶段都出现明显选择收敛

第二轮使用 360 局按阶段统计，而不是把六个阶段混在一起。

| 阶段 | 首选 | 选择率 |
| --- | --- | ---: |
| 北门 | 带人顶住北门 | 91.7% |
| 主灯线路 | 在黑暗里抢修 | 90.8% |
| 诊疗站 | 连续分诊 | 91.1% |
| 社区恐慌 | 重新组织所有人 | **100.0%** |
| 侧街绕后 | 按旧情报改线 | **98.9%** |
| 最后一条线 | 所有人一起守住 | **99.7%** |

这说明当前自动策略几乎总偏向“人物判定”路线，尤其最后三阶段接近单选题。

### 但暂不直接改 DAY29 数值

这里存在明显方法学混杂：审计 AI 的效用函数会给人物判定、专长、设施、路线情报和原则修正较高价值，因此它天然偏好 checked choice。

因此本轮只把它标记为 **强烈需要真人验证的收敛风险**。下一轮应增加：

- 对每阶段三种选项做独立期望值枚举；
- 固定同一 DAY29 状态，仅改变单个资源/原则/情报条件；
- 检查资源方案是否只在“人物状态极差”时才有意义；
- 检查 consequence 方案是否存在真正可接受的战略用途，而不是纯惩罚按钮。

## 4. 资源曲线：出现断崖，但第一轮策略模型有偏差

第一轮所有三类策略都会在中前期把平均口粮压到接近 0；电力也会长期贴近低位。

例如 120 局/策略的压力曲线中：

- 均衡策略平均口粮 DAY7 约 0.65，DAY14 接近 0；
- 谨慎策略 DAY7 约 0.40，DAY14 接近 0；
- 激进策略 DAY7 约 0.48，DAY9 后长期接近 0；
- 电力多数策略在中期长期处于个位数。

**但不能因此直接增加初始口粮或降低消耗。**

原因是第一版自动调度器把“探索 / 医疗 / 守备 / 维修”放在炊事之前，三人开局时可能把所有可行动人物先占掉，导致它比正常玩家更容易制造低质量供餐。这会污染“第一缺粮日”和希望曲线。

### 下一轮方法修正

在任何资源平衡修改前，策略模型必须先改为：

1. 先处理危重医疗；
2. 为当天至少一顿热食预留最低炊事人手；
3. 再决定是否派双人探索队；
4. 最后才把剩余人手分到守备 / 维修 / 广播；
5. 若资源非常紧张，再允许策略主动接受冷食作为明确代价。

只有修正后仍出现同样断崖，才进入数值平衡。

## 5. 居民强度：第一轮没有覆盖到问题本身

600 局基线中：

- 居民峰值 0–4：600 局；
- 5–8：0 局；
- 9+：0 局。

因此第一轮**完全不能回答“后期居民是不是太强”**。

这不是“居民不强”，而是自动策略没有形成足够多的救援/社区型路线。

下一轮必须加入两种补充实验：

- **救援优先策略**：主动追踪居民楼、广播求救、公交站等救援来源；
- **受控居民注入**：在相同 DAY14 / DAY21 状态分别固定 0、5、8、10 名居民，比较食物压力、维修、防御、医疗辅助和最终尸潮成功率。

在拿到 5+ 与 9+ 样本之前，不改居民轮值系数。

## 6. 地点价值：地铁目前明显偏低，但仍需复验

第一轮只有 **地铁入口**低于 2.5% 的访问占比：

- 地铁：127 次，占全部基线访问约 1.1%。

其他地点没有进入自动“死地点”阈值。

不过当前自动地点选择主要看资源缺口、首次访问奖励和危险度，尚未充分给“撤离路线情报”估值。因此地铁偏低可能同时来自：

1. 地铁本身高危险 / 资源回报不够；
2. 策略模型低估路线情报。

下一轮先让策略真正给 `subway_exit_known / evacuation_route_known / southern_route_known` 战略价值，再决定是否调整地铁收益或风险。

## 7. 原则强弱：暂时只保留监控信号

第一轮隔离实验中，DAY14 的 `core-leads` 在当前策略模型下表现最高（Hold+Perfect 7.5%），其他原则大多在 0–2.5%。

但基线整体成功率过低、居民覆盖不足、炊事策略又存在偏差，所以这个差异还不能直接当成平衡结论。

下一轮应在修正策略后重新跑同样的 9×隔离矩阵；若 `core-leads` 仍领先同阶段其他原则 >15 个百分点，再进入实际削弱或替代设计。

## 8. 当前优先级

### P0 — 先修审计方法

- 炊事优先级修正；
- 救援优先策略；
- 受控居民规模实验；
- 地点选择加入战略情报价值；
- DAY29 做阶段内独立期望值分析。

### P1 — 已经可以进入设计修复

- 跨夜事件冷却 / 最近事件降权；
- 增加“同类别但不同现场”的替代事件权重，而不是单纯继续复制事件卡。

### P2 — 等方法修正后再动

- 初始资源；
- 每日口粮消耗；
- 居民轮值强度；
- 九条原则数值；
- 地铁收益 / 危险；
- DAY29 三方案具体数值。

## 9. 决策门槛

后续 balance pass 只有在满足以下条件后开始：

- 三种基线策略的供餐逻辑不再存在明显非玩家式错误；
- 5–8 和 9+ 居民档都有足够样本；
- 地点策略会给路线情报明确价值；
- DAY29 每阶段按独立状态比较，而不是只看一个自动效用函数；
- 重复率修复后重新跑 500+ 基线局确认内容多样性。

在这些条件达到前，当前 v0.6 的玩法数值保持不动。
