# Ember Street v0.5.0 — Living Street QA Matrix

## P0 自动化阻断

以下任何一项失败都不能合并 `main`：

- [x] 七格始终为 7。
- [x] 首局前三个罐头可完成第一次三合与首单。
- [x] 货架同类物资按 3 件一批，前两次点取不换品。
- [x] DAY 1 首单至少 30 秒。
- [x] 满格紧急清台释放空间；第三次才提前收摊。
- [x] 低电力会让尸潮压力增长更快。
- [x] 药品可触发一次医疗请求额外等待时间。
- [x] 轻伤影响后续状态并可通过休息恢复。
- [x] DAY 1 可修搜索站并留下林夏。
- [x] 2D6 使用 seeded PRNG。
- [x] 已有骰子结果再次调用 roll 不会重投。
- [x] 优势 / 劣势使用 3D6 并只保留两颗。
- [x] DAY 1–30 每天存在可生成的街区状况。
- [x] Living Street 内容节点设置 >= 90 的自动门槛。
- [ ] NIGHT 1 → DAY 30 第一章自动贯通。
- [ ] DAY 30 成功才进入 `chapterComplete`。
- [x] 每日挑战 Seed / 挑战码可复现且不写主线。
- [x] 离线收益不上夜间进度。
- [ ] `npm run typecheck` 通过最终 HEAD。
- [ ] `npm test` 通过最终 HEAD。
- [ ] `npm run build` 通过最终 HEAD。
- [ ] `npm run cf:dry-run` 通过最终 HEAD。

> `[x]` 代表对应代码 / 自动测试已经存在；最终发布仍以最新 HEAD 的整套 CI 全绿为准。

## P0 30 天主流程

发布前人工至少完整验证关键节点：

- [ ] NIGHT 1 首单引导明显但不阻塞。
- [ ] DAY 1 天亮后能看懂“街区 / 行动 / 日志”。
- [ ] DAY 1–6 固定章节事件可正常处理。
- [ ] DAY 7 不错误触发章节完成。
- [ ] DAY 8–9 能继续白天 / 黄昏 / 守夜循环。
- [ ] DAY 10 第一轮尸潮正常进入和结束。
- [ ] DAY 11–19 不出现状态死锁。
- [ ] DAY 20 第二轮尸潮正常进入和结束。
- [ ] DAY 21–29 不出现状态死锁。
- [ ] DAY 30 最终尸潮可正常开始。
- [ ] DAY 30 成功后清晰表达第一章完成。
- [ ] DAY 30 失败后可重新准备，不跳 DAY 31。
- [ ] 刷新页面后主线、Story Flags 和已投骰结果能恢复。

## P0 跑团判定

- [ ] 普通判定视觉显示 2D6。
- [ ] 优势 / 劣势视觉显示 3D6，并明确哪两颗被采用。
- [ ] 修正来源能读懂：专长 / 信任 / 伤病 / 建筑 / Story Flag。
- [ ] 2–6 / 7–9 / 10–11 / 12+ 的结果文案与规则一致。
- [ ] 双六反馈明显但不像老虎机。
- [ ] 双一有明显代价，但第一章不造成永久死亡。
- [ ] 信任 3 的角色仅在适用判定获得一次最低骰重投。
- [ ] 投骰后刷新网页不能刷结果。
- [ ] 夜间判定出现时 NIGHT 倒计时暂停。
- [ ] 接受夜间判定结果后倒计时继续。

## P1 事件生态

- [ ] DAY 1–30 每天至少显示一个街区状况。
- [ ] 单日 Story Pool 不一次塞出过多大卡片。
- [ ] 地点事件链能因 Story Flags 继续或结束。
- [ ] 人物事件能体现信任和过去选择。
- [ ] 无选择生活日志能提供世界呼吸感。
- [ ] 夜间动态日志不遮挡七格。
- [ ] DAY 5 / 10 / 15 / 20 / 25 阶段突发能按条件出现。
- [ ] DAY 30 两个关键判定能触发。
- [ ] 过去获得的稳压模块 / 围栏准备 / 路线情报等能修改最终判定。

## P1 夜间手感

- [ ] 订单之间有明显喘息，不连续闪烁刷新。
- [ ] 货架“本批 ×3 / ×2 / ×1”足够清楚。
- [ ] 三合反馈清晰，连续点击不锁 UI。
- [ ] Combo 和极限出餐不遮挡七格。
- [ ] 尸潮五阶段视觉变化可感知。
- [ ] 低电力时更紧，但不是不可玩。
- [ ] 药品医疗容错触发时文案足够明显。
- [ ] DAY 10 / 20 / 30 的节奏差异可感知。
- [ ] 音效关闭 / 震动关闭立即生效。

## P1 白天阅读体验

- [ ] 生存状态优先显示语义而不是只显示数字。
- [ ] 事件正文一屏内能读完主要信息。
- [ ] 选择显示成本 / 风险 / 判定类型。
- [ ] 余烬日志时间、标题、后果层级清楚。
- [ ] 幸存者能看到特性、信任、精力、伤病。
- [ ] 白天整体明显比夜间安静。
- [ ] 到 DAY 15 / 20 / 25 时内容仍没有明显“后半段空洞”。

- [ ] 切后台关键进度强制保存。
- [ ] 返回前台没有重复计时器。
- [ ] localStorage 不可用时至少能开始新游戏。
- [ ] Web Audio 不可用时不崩溃。
- [ ] Vibration 不可用时不崩溃。
- [ ] Clipboard 不可用时主线和分享卡不崩溃。
- [ ] `prefers-reduced-motion` 下骰子与循环动画有静态降级。

## P2 内容一致性

- [ ] DAY 1–6 固定事件与早期主题一致。
- [ ] DAY 10 / 20 / 30 预报和实际强度一致。
- [ ] 林夏、老周、阿禾、程医生、阿梁、小满按 30 天解锁曲线进入。
- [ ] 建筑解锁天数与 GDD / BALANCE 一致。
- [ ] Story Flags 不出现明显互斥状态同时存在。
- [ ] 小灰事件不会被 30 天循环无限重复推进。
- [ ] 第一章完成后灯火等级为 Lv.7。
- [ ] 分享卡能表达 DAY / 灯火 / 街区成长。

## 自动测试文件

- `tests/engine.test.ts`：七格、批次货架、节奏、建筑、资源夜间后果、阶段尸潮预报。
- `tests/narrative.test.ts`：章节事件、日志、选择成本、生存状态、伤病恢复。
- `tests/living-street.test.ts`：DAY 1–30 日常覆盖、内容节点、骰子确定性、刷新不可重投、优势 / 劣势。
- `tests/chapter-flow.test.ts`：NIGHT 1 → DAY 30 第一章贯通。
- `tests/feel.test.ts`：紧急清台、Combo。
- `tests/retention.test.ts`：离线、小灰、自动排班。
- `tests/challenge.test.ts`：每日 Seed 与挑战码。

## v0.5.0 放行条件

1. 功能分支最终 HEAD CI 全绿。
2. NIGHT 1 → DAY 30 贯通测试全绿。
3. Living Street 内容量与骰子确定性测试全绿。
4. 文档与实际 30 天规则一致。
5. 合并 `main` 后主干 CI 再次全绿。
6. `dev` 同步到同一个稳定提交。

完成 1–6 后，v0.5.0 视为代码侧发布完成；人工移动端 QA 继续作为发布后的 P1 验收。
